# 🧠 Интеллектуальная система подбора и скоринга помещений (Tenant Side)

Данный документ подробно описывает механизм работы системы создания поисковых проектов (Search Profiles) и алгоритм автоматической оценки (скоринга) помещений для арендатора.

---

## 1. Концепция поискового проекта (Search Profile)

Для того чтобы система начала давать персонализированные рекомендации, арендатор создает **Проект поиска**. Это набор бизнес-требований и предпочтений, на основе которых алгоритм оценивает каждое помещение в базе данных.

### Параметры проекта:
- **Категория бизнеса**: Например, "Кофейня", "Аптека", "ПВЗ". Используется для анализа конкуренции.
- **Финансовые границы**: Минимальный и максимальный бюджет аренды, диапазон площадей.
- **Технические требования**: Критичные параметры (электрическая мощность, наличие воды, вытяжки, отдельного входа).
- **Геолокация**: Точка центра поиска и радиус (например, "в радиусе 2 км от м. Арбат").
- **Синергия (Желаемые соседи)**: Список категорий бизнеса, соседство с которыми желательно (например, для кофейни это могут быть цветочные магазины или офисы).

---

## 2. Алгоритм скоринга (0–100 баллов)

Каждое помещение проходит через `PropertyScoringService`, который рассчитывает итоговый балл на основе 4 независимых компонентов.

### 💰 Компонент 1: Финансовое соответствие (макс. 20 баллов)
Оценивает попадание объекта в бюджет и площадь.
- **Точное попадание**: 10 баллов за площадь + 10 баллов за цену.
- **Гибкость**: Если объект выходит за границы диапазона не более чем на **20%**, система начисляет частичные баллы (пропорционально отклонению). Если отклонение больше 20% — 0 баллов за критерий.

### ⚙️ Компонент 2: Техническое соответствие (макс. 40 баллов)
Самый весомый блок, так как отсутствие технических условий часто делает аренду невозможной.
- **4 критерия по 10 баллов**:
    1. Наличие мокрой точки (если требуется).
    2. Наличие вытяжки (если требуется).
    3. Отдельный вход (если требуется).
    4. Достаточная электрическая мощность (кВт).
- **Логика**: Если в проекте указано, что параметр *обязателен*, а в помещении его нет — начисляется штраф (-10 баллов за каждый пункт).

### 📍 Компонент 3: Локация и Синергия (макс. 25 баллов)
1. **Расстояние (15 баллов)**:
    - 15 баллов: объект в первой трети радиуса поиска (самый центр).
    - 10 баллов: во второй трети.
    - 5 баллов: на окраине радиуса.
2. **Синергичные соседи (10 баллов)**:
    - Система проверяет поле `existingNeighbors` у объекта.
    - Если среди соседей есть бизнесы из списка "Желаемых соседей" проекта, начисляются баллы пропорционально количеству совпадений.

### ⚔️ Компонент 4: Анализ конкуренции (макс. 15 баллов)
Защищает арендатора от каннибализации трафика.
- **Прямой конкурент**: Если в здании уже есть бизнес той же категории (например, ПВЗ Wildberries при поиске под ПВЗ) — **0 баллов**.
- **Косвенный конкурент**: Если категории разные, но у них общий "родитель" (например, "Пекарня" и "Кондитерская") — **7-8 баллов**.
- **Чистая зона**: Если конкурентов нет — **15 баллов**.

## 3. Визуализация и интерпретация результатов

Итоговый балл трансформируется в цветовую индикацию на карте и в списках:

| Баллы | Статус | Цвет |
| :--- | :--- | :--- |
| **75 – 100** | 🔥 **Отличный мэтч!** | Зеленый |
| **50 – 74** | 👍 **Хороший вариант** | Желтый |
| **25 – 49** | ⚠️ **Частичное совпадение** | Красный |
| **0 – 24** | ❌ **Не подходит** | Серый / Красный |

### Детализация для пользователя:
В карточке объекта арендатор видит не просто цифру, а прогресс-бары по каждому из 4 компонентов. Это позволяет быстро понять, *почему* объект получил низкий балл (например: "Идеальная локация, но не хватает мощности электричества").

## 4. Техническая реализация (Backend)

### Файловая структура (Логика и API):
- **Service**: `PropertyScoringService.java` — «сердце» системы. Содержит математические формулы оценки, расчет расстояний (Haversine) и логику распределения весов.
- **Controller**: `PropertyController.java` — обрабатывает запросы на `/api/properties/recommended`, извлекая активный проект пользователя и запуская процесс скоринга.
- **Integration**: `PropertyService.java` — метод `getRecommendedPropertiesForTenant`, который связывает репозитории и сервис скоринга.
- **DTO**: `ScoredPropertyDto.java` — структура ответа, содержащая объект помещения и детализацию баллов по 4 компонентам.

### Сущности и Репозитории:
- `SearchProfile.java` / `SearchProfileRepository.java` — работа с проектами арендатора.
- `Property.java` / `PropertyRepository.java` — работа с данными о помещениях и их характеристиках.
- `BusinessCategory.java` — иерархия категорий бизнеса для анализа конкуренции и синергии.

## 5. Схема данных (База данных)

Данные для расчета берутся из следующих таблиц PostgreSQL:

| Таблица | Описание данных |
| :--- | :--- |
| **`search_profiles`** | Хранит настройки проектов: бюджеты, площади, тех. требования (вода, вытяжка и т.д.), координаты центра поиска. |
| **`properties`** | Основная таблица помещений: цена, адрес, площадь, тех. характеристики (кВт, вход), координаты. |
| **`business_categories`** | Справочник типов бизнеса. Используется для связи проектов и соседей с конкретными видами деятельности. |
| **`property_existing_neighbors`** | Таблица связи (Join Table). Содержит информацию о том, какие бизнесы уже работают в конкретном здании. |
| **`search_profile_desired_neighbors`** | Таблица связи (Join Table). Хранит список категорий, соседство с которыми желательно для конкретного проекта арендатора. |

---

## 6. Визуализация (Frontend)

Реализация отображения результатов на стороне клиента:
- **Model**: `property.dart` (вложенный класс `ScoredProperty`) — парсинг данных скоринга из JSON.
- **UI Component**: `PropertyDetailsScreen.dart` — методы `_buildScoringCard` и `_scoreBar` для отрисовки графиков и бейджей.
- **Service**: `PropertyService.dart` — метод `getRecommendedProperties`, выполняющий HTTP-запрос к бэкенду.
